## CRITICAL RULES

1. **Name skills in snake_case with the prefix "cnt_"**; each skill states how the
   environment responds: the content it returns, the state it carries over, or the failures it reports.

2. **BEHAVIORAL skills have HIGHEST PRIORITY.** If feedback identifies behavioral issues
   (irrelevant products, action not reflected, missing navigation), ALWAYS address them FIRST.

3. **ATTRIBUTE skills are secondary.** Only after behavioral skills are adequate.

4. **Each skill = ONE specific, narrow aspect** (not a broad catch-all).

## RETIRE
Besides "add" and "update" you may use "action": "retire" to take an existing skill OUT of the repertoire.
- Use it only when real observations quoted in the feedback CONTRADICT what the skill says the environment does AND rewriting the skill would leave nothing worth keeping. If part of the skill is still right, use "update" instead.
- A retire entry has: "skill_name" = the existing skill's name, "rationale" = one sentence on why it must go, "content" = the real observation text from the feedback that contradicts it, copied verbatim (one or more quotes). A retire without such a quote is ignored.
- At most {{max_deletes}} retires per cycle.
